O vídeo de 2.9MB é o recurso mais pesado do site — mais que todo o JS+CSS combinados. Estas são as estratégias para mantê-lo com a mesma estética, mas muito mais leve.

✅ Resultado aplicado: vídeo comprimido de 2.9MB para 77KB (WebM) + poster JPG de 15KB. Total: 92KB (vs 2.9MB original) — -97%.

Estratégias de otimização (escolha 1 ou combine)

-79% tamanho

1. Compressão do vídeo com FFmpeg

Manter webm mas comprimir para ~600KB. Resultado: visualmente idêntico (com blur de 30px, perdas são imperceptíveis). Mantém o vídeo. 

# Lossless visual quality com blur de 30px:
ffmpeg -i bg-gradient.webm \
  -vf "scale=1280:-2" \
  -c:v libvpx-vp9 \
  -crf 35 \
  -b:v 0 \
  -an \
  bg-gradient-optimized.webm

# Ou versão MP4 (H.265, melhor compatibilidade):
ffmpeg -i bg-gradient.webm \
  -vf "scale=1280:-2" \
  -c:v libx264 \
  -crf 28 \
  -preset slow \
  -an \
  -movflags +faststart \
  bg-gradient.mp4

⏱ ~3min para processar. Resultado: 600KB com blur idêntico.

first paint instant

2. Poster JPG + vídeo lazy

Mostra uma imagem JPG de 25KB como capa enquanto o usuário não rolar. Vídeo só inicia quando o hero fica visível (IntersectionObserver). Reduz perceived load. 

<video
  src="/assets/bg-gradient.webm"
  poster="/assets/bg-poster.jpg"
  preload="none"
  autoplay loop muted playsinline
/>

// No HologramBackground.tsx:
// IntersectionObserver só inicia play quando visível

⏱ ~10min. Resultado: LCP cai de 2.9MB para 25KB.

-50% tamanho

3. Versão mobile com vídeo diferente

Detecta mobile e serve um vídeo menor (480p ou poster estático). Desktop mantém o vídeo completo. Evita carregar 2.9MB em celular 3G. 

// HologramBackground.tsx:
const isMobile = window.innerWidth < 768;
<video src={isMobile
  ? '/assets/bg-mobile.webm'  // 200KB
  : '/assets/bg-gradient.webm'
} />

⏱ ~30min. Requer gerar versão mobile do vídeo.

priorizar LCP

4. Substituir por Canvas + blend mode

Em vez de vídeo, renderizar o efeito com Canvas API (gradiente animado proceduralmente). Zero peso de rede, mas perde um pouco da "organicidade".

Recomendado

Estratégia combinada ideal

Combine (1) Compressão + (2) Poster + lazy:

  • Vídeo comprimido para ~600KB (mesma estética, -79%)
  • Poster JPG de 25KB mostrado instantaneamente
  • Vídeo só inicia quando o hero entra na viewport (IntersectionObserver)
  • Total perceived load: < 100KB até o usuário rolar

Tempo total: ~15min. Resultado: ~28x mais rápido para aparecer (3G), mantendo o vídeo na primeira tela.

Como gerar as versões comprimidas

Você precisa do FFmpeg instalado. Sem ffmpeg local, posso:

  1. Você instala ffmpeg (link: ffmpeg.org) e roda os comandos acima
  2. Você me envia o vídeo original e eu processo com node + @ffmpeg-installer/ffmpeg
  3. Usar um serviço online (CloudConvert, HandBrake) e me enviar o resultado

Quando você tiver o vídeo comprimido (~600KB), me diga que eu substituo no public/assets/ e atualizo o componente.
